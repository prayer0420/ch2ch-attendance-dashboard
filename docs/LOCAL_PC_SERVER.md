- https://bonanza-opulently-quack.ngrok-free.dev/ 에서 앱 접속 코드로 로그인할 수 있다. 별도 휴대폰 앱/Tailscale은 필요하지 않다.
- ngrok 터널이 `127.0.0.1:3000`에만 연결한다. 웹 운영 빌드·외부 HTTPS 로그인/로그아웃·비로그인 API 차단을 검증했다. 기존 업무 데이터는 변경하지 않았다.
- Runner도 켜져 있으며 `online/대기 중` 하트비트를 확인했다. 현재 계정의 Windows 로그인 후 웹·Runner·터널 자동 시작을 등록했다. 과거의 비정상 `running` 기록 13건은 수정하거나 재실행하지 않고, Runner는 새 `queued` 요청만 처리한다. 실제 재부팅/로그아웃, 절전 방지, 실제 휴대폰 LTE/5G 확인은 수행하지 않았다. 아래 Tailscale 및 자동 시작 대기 기록은 이전 상태다.
- 시작·중지, 토큰 암호화, 무료 요금제 제한, 검증 및 복구 자료는 [외부 접속 운영 문서](EXTERNAL_ACCESS.md)를 따른다.

## 최신 상태 — 접속 코드 설정 적용 완료 (2026-09-22)

- 사용자가 직접 정한 접속 코드의 암호화 저장을 확인하고, 소유권이 확인된 웹 서버만 종료 후 `-Production -WebOnly`로 재시작했다. 아래 초기 PID는 현재 PID가 아니다.
- `http://localhost:3000/login`에서 설정 필요 안내가 없어졌으며, 실제 HTML 폼 로그인 → 설정 화면 → `/api/app` 200 → 로그아웃 후 401을 검증했다. 비밀번호·쿠키 값은 출력하거나 테스트 파일로 저장하지 않았다.
- 검증 도구: `scripts/server/verify-login.js`. 암호화 설정은 `common.ps1`의 `Import-ServerAuthentication`으로 해당 시험 프로세스에만 전달한다. 업무 쓰기 요청은 검증 중 차단한다.
- Runner는 계속 미실행이다. 기존 13건의 진행 기록도 변경하지 않았다. 휴대폰 연결·자동 시작·절전 설정은 미완료다.

## 대단계 1 — 접속 코드 설정

- 소단계 1: 프로젝트의 `configure-server.cmd`를 직접 실행한다. `New app access code`에 이 앱 전용 코드 12~256자를 입력하고, `Confirm app access code`에 같은 값을 다시 입력한다. Windows나 웹교적 비밀번호를 재사용하지 않는다. 입력은 가려지며 채팅으로 보내지 않는다.
- 소단계 2: `Setup complete`가 나오면 설정 완료다. 기존 `.env.local`은 수정하지 않는다. 기계용 세션/Worker 토큰은 보안 난수로 만들고 표시하지 않는다. 입력 불일치·길이 오류이면 저장하지 않는다. 이미 설정이 있으면 덮어쓰기와 자동 키 교체를 거부한다.

새 설정은 `%LOCALAPPDATA%\CH2CH-Server\<프로젝트 식별자>\auth.dpapi`에 Windows 현재 계정으로 암호화된다. OneDrive 및 Git과 분리되어 있으며 복호화에는 같은 PC·계정이 필요하다. 이 파일은 앞선 프로젝트 백업 시점에는 없던 별도 설정이므로, 설정 후의 백업은 따로 챙겨야 한다. 비밀번호 변경/다른 PC 이전 도구는 아직 제공하지 않는다.

## 대단계 2 — 웹 및 실행기 시작

- 소단계 1: 실행 중인 설정 안내용 서버는 새 값을 자동으로 읽지 않는다. 그 서버의 소유권을 확인해 명시적으로 종료한 후 `scripts/start-local.ps1 -Production -WebOnly`로 먼저 다시 시작하고 로그인·조회부터 확인한다. 설정 완료를 알리면 Codex가 이 단계를 이어서 수행할 수 있다.
- 소단계 2: 기존 실행 기록과 다른 Runner 가동 여부를 검토한 다음에만 `start-server.cmd`로 웹과 Runner를 함께 시작한다. 미검토 대기/진행 작업, 필수 설정 누락, 큐 조회 실패가 있으면 시작하지 않는다. 실제 출석 처리나 QR 시트 수정은 업무 승인을 받은 작업에만 수행한다.

`start-local.cmd`는 개발 모드, `start-server.cmd`는 운영 모드다. 같은 3000번 포트를 공유하므로 동시에 실행하지 않는다. 이미 자기 서버가 켜져 있으면 재시작/중복 실행하지 않고 안내한다. 다른 프로그램이 포트를 사용 중이면 **종료하지 않고 중단**한다.

명시적으로 종료하려면 기존 `stop-local.cmd`를 사용한다. 기록된 PID뿐 아니라 생성 시각·실행 파일·스크립트 경로가 맞는 프로세스만 종료한다. 실행 중인 출석 업무가 있다면 먼저 종료 가능 여부를 확인해야 한다. 이전 버전의 불완전한 PID 기록이나 다른 프로세스는 자동으로 종료하지 않는다. 로그는 실행별 이름으로 남기며 기존 로그·업무 자료는 지우지 않는다.

## 대단계 3 — 상시 운영 및 휴대폰 연결

- 소단계 1: 로그인과 기존 자료 읽기, 승인된 소량 업무 검증을 마친 뒤 Windows 로그인 시 자동 시작과 장애 재시작 방식을 정한다. GUI 브라우저 자동화가 있으므로 현재 사용자 세션의 필요 여부도 확인한다. 현재 자동 시작/장애 복구는 아직 등록하지 않았다.
- 소단계 2: 이 PC를 계속 켜두고 필요한 시간에는 절전되지 않도록 운영 방식을 결정한다. PC 전체 전원 설정은 사용자 승인 후 변경한다. 업데이트·재부팅 시 중단이 발생할 수 있다.
- 소단계 3: 휴대폰 외부 접속은 현재 연결된 ngrok HTTPS 주소로 검증한다. localhost는 다른 기기에서 이 PC를 가리키지 않는다. 인증 문제를 피하려고 보호 기능을 끄거나 일반 HTTP로 개인정보를 공개하지 않는다.

## 검증 결과

- 운영 빌드·API 보안 25개·앱 계약 검사 통과.
- `npm run verify:local-server`: 임시 폴더의 가짜 서버로 실행/종료, 중복 시작 방지, 오래된 PID 기록 거부, 다른 프로그램의 3000번 포트 보존, 로그인 화면 준비 확인을 검증했다. 실제 Runner·DB 변경 없음.
- `node scripts/verify-local-server.js --auth-only`: 임시 사용자 설정 폴더에서 가짜 시험 코드의 암호화 저장→복호화→실행 환경 전달, 평문 출력 없음, 기존 설정 덮어쓰기 거부를 검증했다. 실제 접속 코드를 설정한 시험은 아니다.
- 실제 3000번 서버: 관리자 접속 화면과 설정 필요 안내 표시, `/api/app` 503 차단, 브라우저 오류 없음, loopback만 수신 확인.
- 운영 브라우저 정적 자원 64개에서 현재 로컬 비밀값 일치를 찾지 못했다. 모든 비밀정보 유형에 대한 완전한 감사는 아니다.
- 최종 사용자 로그인·실제 업무 쓰기·모바일 접속·재부팅 후 복구 검증은 아직 미완료다.

운영 파일은 `scripts/server`와 `scripts/start-local.ps1`, `scripts/stop-local.ps1`에 있다. `npm run build:server`는 3000번 포트가 사용 중이거나 기록된 프로세스가 존재하면 기존 서버를 종료하거나 빌드 파일을 덮어쓰지 않고 중단한다.
